Fehler

Fehler werden mit passenden HTTP-Statuscodes signalisiert. Direkte Provider-Antworten werden 1:1 durchgereicht (siehe das 404-Beispiel bei den Consent-Entscheidungen).

Zusammengesetzte Provider-Fehler

Schlägt die automatische Akten-Auflösung über die /insurants/{kvnr}/…-Routen fehl, antwortet die Middleware mit einem zusammengesetzten Fehler aller Provider:

Beispiel — unbekannte KVNR 502 Bad Gateway · application/json

{{ template "json" "{\n \"errors\": [\n {\n \"error\": \"provider_error\",\n \"error_description\": \"http error: 400, error code: malformedRequest, error detail: \",\n \"provider\": 2\n },\n {\n \"error\": \"provider_error\",\n \"error_description\": \"http error: 400, error code: malformedRequest, error detail: \",\n \"provider\": 1\n },\n {\n \"error\": \"provider_error\",\n \"error_description\": \"http error: 400, error code: malformedRequest, error detail: \",\n \"provider\": 3\n }\n ]\n}" }}

Validierungs- und Aktionsfehler

Die KVNR-Endpunkte validieren Eingaben und melden fehlgeschlagene Aktionen im einheitlichen Format {"error", "error_description"}:

Ungültige KVNR 400 Bad Request · application/json

{{ template "json" "{\n \"error\": \"invalid_kvnr\",\n \"error_description\": \"KVNR must be an uppercase letter followed by 9 digits\"\n}" }}

Befugnis-Erteilung fehlgeschlagen 502 Bad Gateway · application/json

{{ template "json" "{\n \"error\": \"entitlement_failed\",\n \"error_description\": \"setting entitlement PS: http error: 409, error code: statusMismatch, error detail: \"\n}" }}

Provider-Fehler (durchgereicht)

Antworten der Provider — auch Fehler — werden unverändert durchgereicht, inklusive Statuscode und Body. Beispiel für eine Anfrage an einen Provider, der die Akte nicht hält:

Beispiel 404 Not Found · application/json

{{ template "json" "{\n \"errorCode\": \"noHealthRecord\",\n \"errorDetail\": \"89GF TLTP 4FCH HKYM\"\n}" }} {{ end }}
