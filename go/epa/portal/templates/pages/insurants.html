Versicherte (KVNR)

Ein Versicherter wird über seine KVNR (Krankenversichertennummer, Format X + 9 Ziffern, z.B. X110611629) identifiziert. Welcher der drei Provider die Akte hostet, ist nicht öffentlich bekannt - die Middleware fragt dazu alle Provider parallel über deren Informationsdienst an.

GET/api/proxies/{name}/insurants/{kvnr}

Umfassende Informationen zu einer KVNR: welcher Provider die Akte hostet, die dort hinterlegten Consent-Entscheidungen und ob über diese Middleware bereits eine Befugnis erteilt wurde. Rein lesend - es wird keine Befugnis erzeugt.

Die Befugnis-Information stammt aus dem lokalen Cache dieser Middleware-Instanz (best effort): ein Neustart leert sie, und die Gültigkeitsdauer beim Provider wird nicht abgefragt.

POST/api/proxies/{name}/insurants/{kvnr}/entitlement

Erteilt explizit eine Befugnis (Entitlement) für die im Proxy konfigurierte Leistungserbringer-Identität. Der Provider wird automatisch ermittelt; optional kann er im JSON-Body erzwungen werden ({"provider": 2}).

Schreibender Vorgang: die Befugnis wird in der Akte des Versicherten hinterlegt - der gewählte Proxy erhält dadurch Zugriff auf die Akte.

GET/api/proxies/{name}/insurants

Listet die diesem Proxy bekannten Zuordnungen KVNR → Provider - also alle Versicherten, deren Akte über diese Middleware-Instanz bereits aufgelöst wurde.

Zugriff auf die Akte

Der Insurants-Pfad ist der bequemste Weg, eine konkrete Akte anzusprechen: man gibt nur die KVNR an, die Middleware übernimmt die Routenermittlung, die Befugnis-Erteilung und das VAU-Tunneling.

So läuft eine Anfrage intern ab:

  1. Erste Anfrage für eine KVNR: die Middleware fragt parallel alle Provider, welcher die Akte hält.
  2. Beim zuständigen Provider erzeugt sie eine Befugnis (Entitlement) für den im Proxy konfigurierten Leistungserbringer.
  3. Das Mapping KVNR → Provider wird gecached, sodass Folge-Anfragen direkt zum richtigen Backend gehen.
  4. Die Anfrage wird inklusive Method, Header, Query und Body durch den VAU-Tunnel weitergeleitet; die Antwort wird transparent zurückgegeben.

Pfad-Schema: /api/proxies/{name}/insurants/{kvnr}/vau/<Provider-Pfad>

Alles nach dem /vau/ ist der originale Provider-Pfad - die offizielle ePA-Dokumentation ist hier 1:1 anwendbar. Beispiele unter Medikation.
